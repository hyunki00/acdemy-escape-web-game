01기획서(포트폴리오용) 작성

HOW

프로젝트 이름, 개요, 게임 구조(상태 관리 · 장면 렌더링 · 인터랙션 · 퍼즐 · 잠금·코드 조합 · 내비게이션 · 엔딩 7개 시스템)를 "구성 → 작동 방식" 형식으로 정리한 기획서를 Word 문서로 작성. 이후 그래픽 자산 파이프라인(실사 촬영 → AI 이미지 생성 → Photoshop 보정)과 오디오 자산 계획(BGM: 생성형 AI, SE: 저작권 없는 무료 음원) 섹션을 추가로 보강함.

WHY

프로젝트가 진행되는 동안 방향을 잃지 않도록, 개발에 본격적으로 들어가기 전에 스스로 "무엇을 만들 것인지 · 어떤 구조로 만들 것인지"를 먼저 명확히 정의해두기 위함. 미리 정리해두면 이후 기능을 추가하거나 수정할 때마다 전체 방향과 어긋나는지 바로 판단할 수 있고, 완성 후에는 포트폴리오 문서로도 바로 활용할 수 있음.

02게임 스크립트 파일을 역할별로 분리

HOW

하나의 HTML 파일 안에 인라인으로 들어있던 자바스크립트 전체(약 670줄)를 아래 8개 파일로 분리함.

파일역할
data.js상태(state) + 퍼즐 · 잠금 · 방 데이터
draw.jsSVG 배경 · 사물 드로잉 함수
ui.js모달 열고 닫기 등 공통 UI
puzzle.js퀴즈(퍼즐) 출제 · 채점
lock.js잠금 · 키패드 · 전원/호출 처리
inventory.js아이템 획득 · 보유 확인
navigation.js클릭 이벤트 위임, 방 이동, 화면 렌더링
main.js타이머 · 설정 · 재시작 · 엔딩, 게임 시작 진입점
WHY

코드가 한 파일에 다 몰려 있으면 특정 기능(퀴즈, 이동, 아이템 처리 등)을 고치려 할 때마다 670줄 전체를 스크롤하며 찾아야 해서 관리가 점점 어려워짐. 개발자로서 코드를 역할별로 구분해두면, 특정 기능을 수정할 때 해당 파일만 열어보면 되고, 앞으로 기능이 늘어나도 구조가 흐트러지지 않아 유지보수가 쉬워짐. 이번 분리로 코드의 구분과 관리, 보수의 용이성을 확보하는 것이 목적.

01실제 학원 전개도 기반으로 이동 동선 수정

HOW

사용자가 촬영한 실제 학원 비상대피도(전개도)를 참고해 방 연결 구조를 수정. 스터디실 연결을 복도(앞) → 복도(뒤)로 이동하고, 관련 퍼즐 요소(게시판, 메모, 문)도 함께 복도(뒤) 화면으로 옮김. 본 강의실 설명에 실제 표지판 문구("5강의실")를 반영.

WHY

실제 대피도를 보면 스터디룸은 엘리베이터 · 인포메이션과 같은 위쪽 구역에 있고, 화장실은 반대쪽 아래 구역에 있음. 게임 속 동선이 실제 공간 구조와 어긋나 있으면 몰입감이 떨어지고, 이후 실사 기반 이미지로 전환했을 때 배경과 동선이 맞지 않아 어색해짐. 미리 구조를 맞춰두면 이미지 자산이 들어와도 자연스럽게 연결됨.

02오디오 자산 제작 착수 — 기본 BGM 완성

HOW

생성형 AI 음악 도구로 게임 전체에 깔릴 기본 배경음악(BGM)을 제작 완료. 실사 이미지의 게임 그래픽화 작업은 현재 진행 중.

WHY

그래픽 자산보다 먼저 완성 가능한 BGM을 확보해, 이후 이미지 자산이 완성되는 대로 바로 오디오까지 함께 적용할 수 있도록 준비 순서를 앞당김.

03이미지 기반 렌더링 시스템 최초 구현 및 복도 배경 적용

HOW

renderImageScene() 함수를 추가해 SVG 대신 실제 이미지 + 퍼센트 좌표 히트박스로 방을 그릴 수 있는 구조를 만들고, AI로 변환한 복도 이미지를 복도(앞) 방에 처음 적용. 마우스를 올리면 노란 테두리로 하이라이트되는 hover 효과도 함께 구현. 이후 생성 오류가 발견된 이미지를 두 차례 교체본으로 재적용함.

WHY

기획서 3.2에 미리 세워둔 "SVG → 이미지 전환" 계획을 실제로 검증해볼 첫 사례가 필요했음. 클릭 영역이 이미지 위에서도 정상 동작하는지 미리 확인해야 나머지 방들도 같은 방식으로 안심하고 진행할 수 있음.

04게임 화면 해상도 확장

HOW

원본 이미지 해상도(2752×1536)를 기준으로 화질이 깨지지 않는 최대 크기를 계산해 게임 프레임을 480px → 1440px로 확장. 이후 화면이 낮은 모니터에서 씬 영역이 프레임 높이를 넘어 이동 버튼과 소지품 바가 잘려서 안 보이는 문제를 발견해, 씬 영역만 유동적으로 줄어들도록 레이아웃 구조를 수정.

WHY

클릭 영역이 좁으면 실제 플레이어가 불편할 거라는 우려와, 원본 이미지 해상도를 다 활용하지 못하고 있다는 점 때문에 확장을 결정함. 화면 크기가 커져도 이동 · 소지품 같은 필수 UI는 항상 보여야 실사용성이 깨지지 않음.

05비상등 깜빡임 연출 추가

HOW

이미지 위에 반투명 빨간 방사형 그라디언트를 mix-blend-mode: screen으로 얹고, 3.4초 주기로 불규칙하게 밝기가 변하는 CSS 애니메이션을 구현.

WHY

정전된 야간 학원이라는 설정을 정지 이미지만으로는 다 표현하기 어려워서, 별도 영상 자산 없이 최소한의 코드만으로 분위기를 강화하기 위함. 영상 자산 제작에 비용을 쓰기 전에 저비용 방식으로 먼저 만족스러운지 검증.

06BGM 파일 연결 및 재생 확인

HOW

업로드받은 bgm.mp3를 Sound 폴더에 배치하고, 기존에 준비해둔 오디오 재생 로직과 연결해 최초 클릭 시 자동재생되는지, 음소거 버튼이 정상 동작하는지 실제 브라우저에서 확인.

WHY

브라우저는 사용자 상호작용 전 자동재생을 막기 때문에, 실제 파일로 재생 흐름을 검증해야 기능이 완성됐다고 확신할 수 있었음.

07테스트용 자유 이동 모드 추가

HOW

DEBUG_FREE_ROAM 플래그를 추가해, 켜두면 퍼즐 클릭이 전부 무시되고 모든 문 · 서랍이 항상 열린 것처럼 처리되도록 분기 처리. 끄면 원래의 정상 플레이 흐름으로 그대로 복귀.

WHY

그래픽 · 레이아웃을 검증하는 단계에서는 매번 퍼즐을 풀며 이동하는 게 비효율적이라, 퍼즐 로직 자체는 건드리지 않고 손쉽게 켜고 끌 수 있는 테스트 우회 경로가 필요했음.

08인포데스크 배경 이미지 적용

HOW

변환된 아카데미 프론트(인포데스크) 이미지를 실제 게임에 적용. 방문자 명단 · 서랍 히트박스 위치는 아직 정하지 않아 TODO 주석만 남기고 보류.

WHY

이미지 자산이 완성되는 대로 바로 반영해 시각적 진행 상황을 눈으로 계속 확인하기 위함. 퍼즐 위치 결정에 시간이 걸리더라도 배경 교체 자체를 미룰 필요는 없었음.
